## 2. 核心交互流程

### 2.1 布局与视觉方向

页面采用浅色研究工作台：浅灰背景、深色文字、蓝色交互强调；涨跌使用红／绿，同时显示正负号和文字。主要通过分栏、留白和分隔线组织信息。

| 区域 | 内容与职责 |
|---|---|
| 顶部 | 虚构股票名称、模拟数据标识、交易所时区、行情范围 |
| 左上，约占主区域 2/3 | K 线、成交量、选中日期、涨跌幅、异动标记、前后异动日按钮 |
| 左下 | 按映射交易日分组的事件时间线 |
| 右侧，约占主区域 1/3 | 当前事件详情、来源原文和证据 |
| 右下浮动面板 | 当前日期的 Agent 解释，支持展开和收起 |

浮动助手展开时，桌面端为它预留空间；窄屏改为底部面板，避免遮挡证据操作。动效仅用于选中高亮、面板展开和定位反馈，并尊重减少动态效果设置。

### 2.2 主要操作路径

1. **进入页面**：加载本地数据，默认选中第一个异动日，同时展示该日事件和解释。
2. **点击 K 线或异动标记**：更新日期、行情摘要、时间线高亮及助手内容；时间线滚动至该日。
3. **点击事件**：打开详情，并选中其映射交易日。详情保留原始发布时间、交易所时间和映射原因。
4. **点击助手中的因素或证据链接**：定位对应事件，打开证据；一个因素涉及多个事件时，每个引用均可单独定位。
5. **选择没有事件的日期**：保留行情，清空旧详情，助手说明当前没有可用因素。
6. **查看范围外事件**：展示事件详情和映射状态；该日缺少行情时，助手明确说明无法生成异动解释。

### 2.3 状态管理

交互状态由根组件统一持有：

```text
scenario
loadState
selection = { tradingDate, eventId }
agentExpanded
```

涨跌幅、相关事件、详情和因素均从这组状态派生。组件通过明确的选择操作更新状态，不各自保存一份“当前日期”。

切换场景时重置选择；切换日期时，如果原事件不属于新日期，则选择该日第一条事件，没有事件就清空。图表悬停只显示提示，不改变选中日期。

对于已映射但没有行情的事件，选择状态记录其映射日期和事件，图表显示该日无行情提示，助手清空旧解释。对于无法映射的事件，日期为空，仅展示事件详情及原因，不生成价格解释。

## 3. 数据结构与业务规则

### 3.1 数据组织

所有公司、来源和事件都明确标为模拟，不使用真实机构名称营造真实性。来源原文保存在项目内，可直接展开核对。

| 数据 | 主要字段 | 示例与约束 |
|---|---|---|
| 股票与市场配置 | `stockId`、`name`、`timezone`、`priceUnit`、`sessions` | `SIM001`、澄川科技、`Asia/Shanghai`；金额以分保存 |
| K 线 | `date`、`open`、`high`、`low`、`close`、`volume` | `close: 1090` 表示 10.90 元；日期唯一且属于交易日 |
| 交易日历 | `coverageStart`、`coverageEnd`、每日 `date/isTradingDay/reason` | 覆盖范围内每天都有记录，休市不能靠“没有数据”推断 |
| 事件 | `id`、`stockId`、`title`、`publishedAt`、`type`、`assertion`、`sourceId`、`summary`、`evidenceIds`、`financialIds` | 类型区分公告、新闻、行业事件和财务披露；陈述区分事实和观点 |
| 来源原文 | `id`、`publisher`、`title`、`publishedAt`、`sections` | 每段有稳定的 `sectionId`，便于定位 |
| 证据 | `id`、`eventId`、`sourceId`、`sectionId`、`quote` | 引文必须能在指定原文段落中找到 |
| 财务数据 | `id`、`stockId`、`period`、`metric`、`value`、`unit`、`comparison`、`publishedAt`、`sourceId` | 如净利润 1.28 亿元、上年同期 1.00 亿元；保留披露时间 |
| 因素候选 | `id`、`tradingDate`、`eventIds`、`financialIds`、`claim`、`mechanism`、`limitations`、`priority` | 预设解释内容，运行时检查时间和证据，再生成展示结果 |

事件示例：

```json
{
  "id": "evt-earnings",
  "stockId": "SIM001",
  "title": "公司披露季度净利润同比增长28%",
  "publishedAt": "2026-03-06T18:00:00+08:00",
  "type": "announcement",
  "assertion": "fact",
  "sourceId": "src-earnings",
  "summary": "模拟公告披露净利润1.28亿元，上年同期1.00亿元。",
  "evidenceIds": ["ev-earnings-profit"],
  "financialIds": ["fin-net-profit"]
}
```

它会映射至 `2026-03-09`。关联因素的表达为：

> 因果假设：业绩改善可能影响市场预期。依据为公告和财务数据；置信度中。尚无市场预期或对照分析，不能确认它导致了当日上涨。

映射结果、涨跌幅和最终解释均由规则计算，不在多个数据文件中重复维护。

### 3.2 模拟故事与覆盖范围

行情覆盖 `2026-03-02` 至 `2026-03-27`，约 20 个交易日，另提供前一交易日的收盘基准。交易日历覆盖 `2026-02-27` 至 `2026-04-03`，并将 `03-18` 明确设为**模拟休市日**。该日历不代表真实交易所日历。

| 场景 | 预设数据与展示目的 |
|---|---|
| 上涨异动 | `03-06` 收盘 10.00 元，`03-09` 收盘 10.90 元，涨幅 9% |
| 上涨日前公告 | `03-06` 18:00 发布业绩公告，映射至 `03-09` |
| 周末行业事件 | `03-07` 发布模拟行业政策，映射至 `03-09` |
| 下跌异动 | `03-12` 收盘 11.00 元，`03-13` 收盘 10.12 元，跌幅 8% |
| 下跌相关事件 | `03-12` 盘后订单取消公告，以及 `03-13` 盘中评论 |
| 未来信息 | `03-13` 16:00 发布后续消息，必须排除在 `03-13` 解释之外 |
| 工作日休市 | `03-18` 事件映射至 `03-19`，证明规则使用日历 |
| 行情范围外 | `03-27` 盘后事件映射至 `03-30`，但没有对应行情 |
| 日历不足 | `04-03` 盘后事件需要更晚的日历，不能直接推断下一交易日 |

总计准备约 14 条事件，并安排一个有行情、无事件的普通交易日。

### 3.3 异动判定

```text
涨跌幅 = (当日收盘价 − 前一交易日收盘价) / 前一交易日收盘价
异动条件 = |涨跌幅| ≥ 5%
```

价格以整数“分”保存，阈值比较使用整数交叉相乘，避免边界受到浮点显示误差影响；百分比仅在展示时保留两位小数。

前收盘基准只用于计算，不强制显示。规则不处理复权、除权、停牌或不同市场的涨跌幅限制，页面称为“演示异动阈值”。

### 3.4 时间转换与交易日映射

先将带 `Z` 或偏移量的 ISO 时间解析为绝对时刻，再转换为 `Asia/Shanghai`。不使用浏览器所在时区推断事件日期；事件排序也按绝对时刻排序。

| 交易所当地时间 | 映射结果 |
|---|---|
| 交易日开盘前 | 当日 |
| 交易时段 | 当日 |
| 午间休市 | 当日 |
| 恰好 `15:00:00` | 当日 |
| 晚于 `15:00:00` | 日历中的下一交易日 |
| 周末或明确休市日 | 日历中的下一交易日 |
| 事件日期不在日历覆盖内，或找不到下一交易日 | 标记“日历不足，暂无法映射” |

模拟交易时段为 `09:30–11:30`、`13:00–15:00`。午间休市和收盘边界是本演示的明确约定，不声称代表所有交易所规则。

实现使用显式时区格式化及日期分量提取，参见 [Intl.DateTimeFormat 文档](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)。

### 3.5 解释截止时间与证据边界

解释固定为“截至所选交易日收盘”：

- 事件、来源和财务披露时间都必须不晚于截止时间。
- 默认因素只使用映射到该日的事件；本版不自动检索跨日背景。
- 财务报告期不能代替披露时间。旧报告期的数据在首次披露前也不可使用。
- 同日归组只说明日级时间相关性。没有分钟行情，不能判断消息发布前后价格变化，也不能据此解释全日涨跌。

标签采用两个维度：

| 维度 | 标签及含义 |
|---|---|
| 信息本身 | **事实（模拟）／观点** |
| 对价格的解释 | **时间相关性／因果假设** |

Agent 使用固定候选与规则，不生成自由文本推理：

1. 取当前日期的候选因素。
2. 检查关联事件、财务数据和证据是否符合截止时间。
3. 按预设优先级展示最多 3 个。
4. 每条展示依据、作用机制、置信度和局限，并提供事件链接。

置信度仅表示证据支持程度。直接披露、有具体事实且机制清楚的候选可以为“中”；只有观点或缺少关键材料时为“低”。本模拟数据不输出“高”，所有因果假设都显示“尚未证实”。

证据不足属于合法业务状态，不等于数据格式错误。没有合格因素时不凑数；预设的两个主要异动日保证各有 1～3 个可展示因素。

### 3.6 状态与异常处理

数据仅在加载入口统一校验一次，检查时间格式、OHLC 关系、日期唯一性和引用完整性。内部模块信任校验结果；无效数据不自动修复或静默跳过。

| 状态 | 页面表现 | 复现方式 |
|---|---|---|
| 加载 | 骨架屏，禁用日期操作 | 加载场景暂停完成步骤，点击“完成加载”继续 |
| 空行情 | 空态，清空选中日期和旧解释 | 选择“空行情” |
| 空事件 | 行情正常，时间线和助手显示无可用事件 | 选择“空事件”或指定普通日期 |
| 范围外事件 | 显示映射日期及缺少行情提示，仍可查看来源 | 选择对应事件 |
| 日历不足 | 显示无法映射，不参与解释 | 选择对应事件 |
| 异常数据 | 显示问题记录及字段，停止绘图和解释 | 选择非法时间或非法 OHLC 场景 |
| 证据不足 | 保留观点出处，展示低置信度和证据缺口 | 选择弱证据因素 |

场景入口收纳在“演示场景”面板，支持一键恢复。正常加载不增加人为等待。
